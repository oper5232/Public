## 1. 평가 목적과 고정 원칙

목표는 대기업 제조사업장의 생산설비 전기 유지보수·전기보전으로 이직할 기회를 찾는 것이다. 변압기·전력기기 정비경력을 활용할 수 있는 정도와 PLC·인버터·전동기·MCC·생산설비 고장진단으로 확장할 수 있는 정도를 구분한다. 기술을 배울 기회를 이미 보유한 실무경력으로 계산하지 않는다.

| 축 | 의미 | 출력 |
| --- | --- | --- |
| 지원 가능 Gate | 명시된 필수조건에 지원할 수 있는가 | 지원가능/조건부지원/지원곤란 |
| 채용 적합도 | 실제 업무와 사용자 경험이 얼마나 맞는가 | 0~100 또는 미산출 |
| 회사 매력도 | 보상·회사·고용·복지·경력가치가 얼마나 매력적인가 | 0~100 또는 미산출 |
| 최종 지원 우선순위 | 두 점수를 결합한 비교 지표 | 적합도×0.6 + 매력도×0.4, 또는 미산출 |

점수는 합격확률·실제 연봉·채용사의 판단을 예측한 확률이 아니다. 아래 구간은 이 프로젝트의 의사결정 규칙이며 공식 채용 기준이나 시장 통계가 아니다. v1.0에서 범위를 닫아 실행 가능하게 정하되, 향후 변경은 사용자 합의와 규칙 버전 변경으로 관리한다.

## 2. 입력·근거 계약

### 2.1 필수 입력

- Jobs의 공고ID·정규화 버전·지원단위, Sources의 정확한 버전·확보 수준·본문.
- 사용자 확인 경력 스냅샷, 평가 기준일, 실제 담당 범위·기간·자격·학력. Career Master가 아직 없으면 같은 논리 구조의 확인된 입력 스냅샷을 사용한다.
- 승인 전에는 점수를 확정하지 않고 후보 선별정보만 표시한다. 승인 후 정식 Jobs로 저장된 공고만 점수 분석 대상이 된다. 승인 후 조사 자료의 입력에는 승인 이벤트ID가 필요하다.
- 회사 보상 비교에는 사용자가 정한 세전 연간 비교 기준액과 그 구성·기준연도가 필요하다. 현재 연봉이나 희망 연봉을 임의로 채우지 않는다.

### 2.2 근거와 신뢰도

| 신뢰도 | 기준 | 숫자 확정 사용 |
| --- | --- | --- |
| 높음 | 해당 법인·직군·기간에 적용되는 공식 원문 또는 사용자가 확인한 자기 경력, 상충 없음 | 가능 |
| 보통 | 적용 범위가 맞는 복수 독립 자료 또는 명시적 근거에 기반한 직무 해석. 핵심 상충 없음 | 가능, 해석·추정 표기 |
| 낮음 | 단일 익명 후기, 다른 직군·법인 수치, 오래된 정보, 불명확한 의미 추정 | 불가, 미확인 처리 |
| 판단불가 | 관련 근거 없음 또는 해결되지 않은 핵심 상충 | 불가, 미확인 처리 |

신뢰도에 임의의 확률을 붙이지 않는다. AI의 자신감 문장만으로 신뢰도를 올리지 않는다. 동일 원자료를 복제한 여러 사이트는 독립 근거가 아니다. 사용자 자기 경력의 ‘확인’은 사용자 제공 사실 기준이며 채용사의 증빙 인정과는 구분한다.

보상·복지 자료는 원칙적으로 평가 기준연도 또는 직전연도의 같은 적용 대상을 사용한다. 더 오래된 자료는 공식적인 현행 적용 확인이 없으면 현재 점수에 사용하지 않는다. 직무·채용요건은 해당 모집 원문 버전을 사용한다. 고용안정성의 재무 관찰기간은 5.3절의 별도 규칙을 따른다.

모든 확정 점수에는 근거ID와 판단 이유가 필요하다. ‘없음’도 명시적 확인 근거가 있어야 하며 원문에 언급이 없다는 사실만으로 0점을 부여하지 않는다.

## 3. 지원 가능 Gate 및 Hard Gate

### 3.1 요건의 논리 구조

원문 필수요건을 원자 조건으로 나누고 원문의 AND/OR를 보존한다. 예를 들어 ‘전기기사 또는 전기산업기사’는 OR, ‘관련 전공 및 경력 2년’은 AND다. 자격·학력·경력·명시된 수행조건 등의 독립 요건군을 최상위 AND로 묶는다. 하나의 요건을 표현만 바꿔 중복 계수하지 않는다.

| 조건 결과 | 판단 |
| --- | --- |
| 충족 | 원문 조건과 사용자 확인 사실의 대응 근거가 있음 |
| 미충족 | 명시된 조건을 충족하지 못한다는 사실이 확인됨 |
| 미확인 | 공고 해석·사용자 사실·채용사 인정범위 중 하나가 불명확 |
| 해당없음 | 조건부 요건의 적용 대상이 아니라는 근거가 있음. 상위 계산에서 제외 |

AND: 미충족이 하나라도 있으면 미충족, 그 외 미확인이 있으면 미확인, 나머지는 충족. OR: 충족이 하나라도 있으면 충족, 그 외 미확인이 있으면 미확인, 나머지는 미충족. 모든 자식이 해당없음이면 해당없음이다. 해당없음은 근거 없이 우회용으로 사용하지 않는다.

| 최종 Gate | 규칙 | 필수조건 충족 여부 |
| --- | --- | --- |
| 지원곤란 | 최상위 독립 필수 요건군 중 확인된 미충족이 하나 이상 | 미충족 |
| 조건부지원 | 확인된 미충족은 없고 미확인 존재 또는 필수요건 구역 미확보 | 일부미확인 |
| 지원가능 | 적용되는 필수 요건군이 모두 충족되고 필수요건 구역 확인 완료 | 충족 |
| null | 분석 자체가 아직 수행되지 않음 | 미평가 |

전체 공고에서 필수요건이 없다는 사실까지 확인되면 적용 조건 0개인 지원가능이 허용된다. 검색 요약에 필수조건이 보이지 않는 것은 이에 해당하지 않는다. 분석이 실행되었지만 필수요건 구역을 못 읽었다면 조건부지원이다.

### 3.2 Hard Gate 판정 지침

| 유형 | 지원곤란이 되는 경우 | 미확인으로 남기는 경우 |
| --- | --- | --- |
| 자격 | 필수 지정 자격의 미보유가 확인되고 대체 인정 조건도 없음 | 사용자 자격 확인 전, 유사 자격 인정범위 불명확 |
| 학력·전공 | 명시적 필수 학력/전공을 충족하지 못함 | ‘초대졸’이 최소인지 한정인지 불분명, 동등학력 인정 미확인 |
| 경력 하한 | 공고의 기준일과 인정범위가 명확하고 인정 경력이 하한 미만 | 현재 재직기간은 알지만 해당 직무 경력 인정 여부 불명확 |
| 경력 상한 | 공고에 명시적 지원 상한이 있으며 이를 초과 | ‘1~3년 우대’ 등 선호 범위를 상한으로 오해할 가능성 |
| 특정 기술 | PLC 실무 등 필수 경험을 명시하고 사용자 미보유가 확인됨 | 경험 정보가 없거나 사용자 수행 범위 불명확 |
| 근무·입사 조건 | 명시적 필수 입사일·교대 등과 사용자 확인 제약이 충돌 | 사용자 가능 여부가 미확인 |

신입 전형에 현재 경력이 있다는 이유만으로 탈락 처리하지 않는다. 경력 1~3년은 수집 선호 범위이며 그 자체가 사용자 지원 자격이 아니다. ‘필수’와 ‘우대’를 구분하며 대기업·정규직 선호, 지역, 교대 여부는 사용자 기준에 없는 Hard Gate를 만들지 않는다.

경력은 공고가 지정한 기준일을 우선하며 없으면 평가 기준일을 사용해 그 사실을 남긴다. 월 단위 요건은 완료한 달 수로 비교하고, 겹치는 재직기간은 중복 합산하지 않는다. 예: 2025-04-21부터 2026-10-05는 완료 17개월이며 2년을 충족하지 않는다. 실제 경력 인정 여부가 확인되어야 Hard Gate에 적용한다. 군복무·현장실습을 공고 근거 없이 관련 정규 경력에 합산하지 않는다.

법적 선임 자격 등 외부 규정 해석이 필요한 요건은 현행 근거를 별도로 확인하기 전까지 미확인이다. 이 문서가 법정 자격요건을 대신 규정하지 않는다.

모집 마감 여부는 Jobs의 모집 상태로 관리한다. Gate는 자격 판정이며 마감으로 점수를 0으로 바꾸지 않는다. 마감 공고는 활성 추천에서 분리한다.

## 4. 채용 적합도 — 100점

각 표는 확정 근거가 있을 때만 적용한다. 근거가 부족하면 6절의 null·범위 규칙을 따른다.

### 4.1 직무 일치도 — 30점 (`job_match`)

실제 주업무를 한 유형으로 선택한다. 제목, Job Family의 P1/P2 표기는 직접 배점하지 않는다.

| 점수 | 담당업무 기준 |
| ---: | --- |
| 30 | 제조 생산설비 전기보전·예방정비·고장진단이 주업무 |
| 26 | 제조사업장 수변전·전력 유틸리티 운영 및 유지보수가 주업무 |
| 24 | 변압기·전력기기 정비·시험이 주업무 |
| 20 | 비제조 시설의 전력·전기설비 유지보수가 주업무 |
| 18 | 전기 설비기술·공무에서 설계·공사·투자관리가 주업무이고 유지보수는 일부 |
| 12 | 전기안전관리·점검·법정 관리가 주업무, 직접 정비는 제한적 |
| 8 | 전기 시공·설계가 주업무이고 유지보수 업무가 없음이 확인됨 |
| 0 | 전기 유지보수·전력기기와 무관한 주업무로 확인됨 |

점수 사이 임의 보간은 하지 않는다. 원문에 핵심/주요 역할이 명시되면 이를 우선한다. 복합 직무에서 주업무를 판단할 근거가 없으면 후보 유형의 최저·최고 점수를 범위로 남기고 단일 점수는 null이다. 단어 빈도나 첫 번째 업무만으로 주업무를 단정하지 않는다.

### 4.2 현재 경력 활용도 — 25점 (`experience`)

다음 다섯 수행역량을 각 5점으로 평가한다. 작업설비 자체의 일치는 4.4절에서, 수행 과정의 전이 가능성은 여기서 판단한다.

| 하위항목 ID | 평가 역량 |
| --- | --- |
| `inspection` | 점검·예방정비·상태관리 |
| `diagnosis` | 측정·시험·진단 데이터 해석 |
| `repair` | 분해·교체·수리 등 실제 정비 수행 |
| `safety` | 작업 준비·안전절차·위험요인 관리 |
| `records` | 정비기록·이상 보고·업무 협업 |

공통 채점: **5점**은 해당 공고 업무에 직접 대응하는 실제 수행 사례와 본인 범위 확인, **3점**은 관련된 실제 업무지만 보조 역할이거나 적용 범위 차이 존재, **1점**은 교육·대학 프로젝트만 확인, **0점**은 사용자에게 해당 경험이 없다는 확인 또는 완전한 공고 확인 결과 해당 역량을 활용하지 않는 직무임이 확인된 경우다. 기록이 없으면 null이다. 실제 반복 업무의 사례는 정량 성과가 없어도 근거가 될 수 있다.

현장실습·군 경험도 실제 역할이 대응되면 사용하되 전기정비 경력으로 바꿔 쓰지 않는다. 같은 업무가 여러 역량을 보여 줄 수 있으나 각 역량별 설명이 필요하다.

### 4.3 필수요건 충족도 — 20점 (`requirements`)

최상위 독립 요건군을 동일 비중으로 평가한다. OR로 묶인 자격 선택지는 한 군이며 항목 수를 늘려 가점을 받지 않는다.

- 적용 요건군 수 N, 충족 P, 미충족 F, 미확인 U라 할 때 N=P+F+U.
- 필수요건 구역을 완전히 확보했고 U=0이면 점수=20×P/N.
- N=0이며 명시적 필수요건 없음이 확인되면 20점. 이는 ‘지원 제한 없음’의 규칙 점수이며 능력 증명이 아니다.
- 구역은 확보했으나 U>0이면 점수=null, 하한=20×P/N, 상한=20×(P+U)/N.
- 필수요건 구역 자체가 불완전하면 점수=null, 범위=0~20. 발견된 미충족의 Gate 효과는 유지한다.

필수 한 가지 미충족이 있으면 이 항목에 일부 점수가 있어도 Gate는 지원곤란이다. 점수로 Hard Gate를 상쇄하지 않는다.

### 4.4 설비·기술 연관성 — 15점 (`technology`)

상위 기술군은 검색·표시용이다. 점수는 **공고에서 실제 요구하는 세부 작업**과 사용자 수행 근거를 대조한다. 같은 기술군 이름만으로 실무 계수 1을 부여하지 않는다.

| 기술군 | 구분할 세부 작업 예시 | 자동 등치 금지 |
| --- | --- | --- |
| 변압기·절연진단 | 외관점검, 채유, DGA 측정, DGA 해석, 수분·전산가·내전압 시험, 여과·갱유, 본체 정비 | 채유와 DGA 진단 해석, 절연유 시험과 본체 정비 |

본문의 핵심 담당업무에서 세부 작업 목록을 확정한다. 동의어·같은 작업의 반복 표현은 합치고, 설비 이름이 다르더라도 별도의 수행 역량이면 분리한다. 우대에만 등장하는 작업은 여기서 제외한다. 공고가 ‘전기설비 유지보수’처럼 넓게만 쓰여 있으면 AI가 상세 작업을 만들어내지 않고 이 항목을 미확인으로 둔다.

각 요구 작업의 대응계수: **1** 같은 세부 작업의 실제 수행 범위 확인, **0.6** 인접 작업의 실제 수행과 구체적인 전이 근거·차이 설명 가능, **0.2** 해당 작업에 연결되는 교육·프로젝트만 확인, **0** 해당 작업 경험 없음 확인. 경력 정보가 없으면 null이다. 보조 수행만 확인되고 핵심 작업 직접 수행이 확인되지 않으면 계수 1을 줄 수 없으며 구체적 전이 근거가 있으면 0.6, 그마저 불명확하면 null이다.

확정 요구 작업 K개를 동일 비중으로 계산한다: 15×계수합/K. 일부 미확인 계수는 0~1 범위로 계산하고 score=null이다. 요구 작업 목록 자체가 불명확하면 전체 범위=0~15다. 완전한 공고에서 전기 관련 기술 요구가 없음을 확인하면 0점이다. 이는 기술 가짓수의 보상이 아니라 공고가 요구하는 작업의 대응 비율이다.

출력 `technology_matches`에 task_id, 요구작업, 사용자 작업 근거, 계수, 양측 근거ID, 판단 이유를 남긴다. 공고 요구 작업 목록·판별 완료 여부는 입력 스냅샷에 보존한다. 기술군은 일치해도 작업이 다르면 별도 판단한다. 목록 미확정 시 matches는 빈 목록이며 reason에 미확정 이유를 명시한다.

### 4.5 우대조건 충족도 — 10점 (`preferred`)

독립 우대 요건군을 중복 제거하고 동일 비중으로 평가한다. 10×충족군수/적용군수. OR 선택지는 한 군이고 부분적으로 관련 있다는 이유로 충족 처리하지 않는다. 미확인군이 있으면 4.3절과 같은 방식으로 null·하한·상한을 계산하되 배점은 10이다.

완전한 공고에서 우대조건이 없음을 확인하면 **5점의 중립 규칙값**을 사용하고 reason에 명시한다. 공고 구역을 못 읽었거나 ‘기타 우대’가 불명확하면 null, 0~10이다. 필수조건과 **논리적으로 같은 조건**을 그대로 반복한 우대만 제거한다. 최소요건보다 높은 수준 또는 별도의 역량을 구별하는 우대는 유지한다. 필수요건을 충족한 모든 지원자가 해당 우대를 자동 충족하는지 검토하며, 해석이 불명확하면 제거하지 않고 미확인으로 남긴다. 중복 제거 후 남는 우대가 없으면 동일하게 5점이다.

## 6. 정보 누락·범위·총점·등급

### 6.1 단일 점수를 만들지 않는 경우

각 평가 항목 및 하위항목은 `score`, `lower`, `upper`, `confidence`, `evidence_ids`, `reason`을 가진다.

- 판단 가능: score=계산 점수, lower=upper=score. 중립 규칙값도 근거와 규칙을 남긴다.
- 미확인: score=null. 단서가 없으면 0~해당 배점, 일부 사실이 있으면 그 사실에 따른 더 좁은 가능 범위.
- 범위는 **미확인 정보에 따른 점수 가능 범위**이며 통계적 신뢰구간·예상 연봉범위·예측 분포가 아니다.
- 한 축의 모든 항목 점수가 산출된 경우에만 total을 합산한다. 하나라도 null이면 그 축 total=null. 대신 lower·upper를 각각 합산한다.
- 최종점수는 두 축 total이 모두 있을 때만 0.6/0.4로 계산한다. 없으면 null이며 최종등급도 null이다. 최종 범위는 두 축 하한/상한에 같은 가중치를 적용한다.
- 모르는 항목을 0점·중간점으로 넣거나 남은 항목을 100점으로 재환산하지 않는다. 범위 하한을 최종점수 칸에 저장하지 않는다.

복지 등 하위항목을 가진 항목은 하위 점수를 합산한다. 하위 하나라도 null이면 항목 score=null이고 lower·upper는 하위 범위의 합이다. 요건·기술·우대 비율은 해당 절의 분모를 보존한다.

### 6.2 정보 충족률과 평가 상태

정보 충족률은 단순 필드 개수가 아니라 **점수가 산출된 최상위 항목의 배점 합/100×100%**다. 두 축별로 계산한다. 하위항목 일부만 확인된 항목은 해당 항목 전체를 미완료로 센다. 부분 확인 내용은 범위와 근거로 보여 준다. 이 보수적 정의로 버전 간 계산을 일관되게 유지한다.

한 축의 신뢰도는 점수 산출에 사용한 근거 신뢰도의 최저값으로 하되, 미산출 항목이 있으면 ‘판단불가’로 둔다. 항목별 신뢰도는 별도로 보존한다. 정보 충족률과 신뢰도는 같은 개념이 아니다.

| 상황 | Analyses 평가 상태 |
| --- | --- |
| 초기/재분석, 두 축 모두 산출 | 잠정 |
| 승인 후 조사반영, 두 축 모두 산출 | 조사반영 |
| 어느 축이든 미산출 | 정보부족 |

‘조사반영’도 추정치가 사실로 확정되었다는 의미가 아니다. 분석 종류는 평가 상태와 별도로 유지한다. 이전 분석의 입력 버전이 달라지면 Jobs는 재평가필요로 표시하되 과거 Analyses는 변경하지 않는다.

### 6.4 승인 전 검토 정보와 승인 후 비교 — v1.2

**승인 전 후보 목록은 점수 순위가 아니라 사용자 검토용 선별정보로 구성한다.** 승인 전에는 정식 Gate·채용 적합도·회사 매력도·최종점수를 산출하지 않는다.

1. 활성 검토에는 검토대기 상태의 후보를 포함한다. 수집 대상외·분류 미해결은 별도 보관한다. 의심분리는 중복 가능성을 표시하고 포함할 수 있다. 보류·제외·승인 후보는 각각 별도 화면/필터에서 확인한다.
2. 승인 전에는 출처·원문 링크, 제목, 회사·실제 고용주 확인 여부, 직무·사업장, 고용형태, 경력조건, 게시·마감일, 원문 확보 수준, 수집 판정·사유, 중복 의심, 전기보전 관련 키워드, 누락정보, 수집 시각을 표시한다.
3. 승인 전 기본 정렬은 목표 직무 직접성 → 경력조건 확인 가능성 → 마감 임박도 → 기업 규모 확인 여부 → 수집 시각이다. 이는 점수가 아니다.
4. 승인 후 정식 저장과 원문·정규화 검증이 완료된 뒤에만 Gate·채용 적합도·회사 매력도·최종점수·등급을 산출한다. 정보부족이면 해당 점수를 null로 유지하고 누락 항목을 표시한다.
5. 승인 후 ‘종합 비교’에서는 같은 Gate 구역의 완전 산출 공고끼리 최종점수 내림차순 → 적합도 내림차순 → 마감일 오름차순 → 공고ID 순으로 정렬한다.

예: 승인 전에는 A·B 모두 점수 없이 기본정보로 검토한다. A를 승인하면 정식 저장 후 분석을 수행하고, B를 보류하면 B는 후보 상태로 남는다. 승인 전 후보에 임의의 적합도·최종점수를 표시하지 않는다.

## 7. AI 판단과 규칙 기반 처리의 경계

| 작업 | AI | 규칙 기반 검증·계산 |
| --- | --- | --- |
| 직무·주업무 분류 | 근거 인용, 후보 유형·불명확성 추출 | 허용 유형·점수표 적용 |
| 경력 활용·기술 대응 | 실제 경험과 업무의 연결 설명 | 미확인 경험 생성 금지, 허용 단계계수 적용 |
| 필수/우대 해석 | 조건 추출, AND/OR 후보 구조 | 원문 검증, 조건별 사실 대조, Gate·비율 계산 |
| 보상·복지·회사 정보 | 제공 자료의 적용 범위와 상충 분석 | 포함항목·기준연도·비교액·구간 계산 |
| 합계·등급·충족률 | 확정 권한 없음 | n8n에서 재계산, 범위·스키마·근거ID 검증 |
| 승인·사용자 경력 | 수정 권한 없음 | 현재 승인·입력 버전 검증, 사용자 확인 사실 보존 |

AI는 자유 숫자 대신 항목별 단계 판단을 제안하고, 정해진 채점 규칙을 거친 결과만 유효 분석으로 발행한다. 아래 JSON은 AI의 무검증 응답이 아닌 **검증 완료 후 저장할 평가 결과 계약**이다.

## 8. 테스트 사례 — SK하이이엔지 유형

**‘SK하이이엔지의 반도체 전기설비 운영 및 유지보수 유형’을 떠올릴 수 있는 합성 공고다. 실제 SK하이이엔지의 현재 공고·자격요건·기업규모·연봉·복지를 조사하거나 평가한 결과가 아니다. 모든 기업 조건·비교 연봉은 테스트 입력이며 실제 DB에 넣지 않는다. 사용자 경력도 아래 사례에서 가정한 확인 범위를 실제 경력에 추가하지 않는다.**

### 8.1 합성 입력

- 제조사업장 수변전·전력 유틸리티 운영 및 유지보수가 주업무. 가상의 요구 세부 작업은 변압기 외관점검과 절연유 내전압 시험 두 가지로 한정한다. 보호계전기 시험·정정 경험을 가정하지 않는다.
- 필수 독립 요건군 3개: 전기 관련 학력, 전기기사 또는 전기산업기사, 인정 관련경력 12개월 이상. 예시 지원자는 세 조건을 충족한다고 가정.
- 우대 2개: 전기기사, 산업안전기사. 전기기사 우대는 산업기사만 보유한 지원자와 구분하므로 유지한다. 예시 지원자가 기사와 산업안전기사 모두 보유한다고 가정하여 2군 모두 충족으로 평가.
- 예시 수행역량: 점검 직접 수행 5, 시험 직접 수행 5, 수리 보조 3, 안전 관련 현장 보조 3, 기록·보고 직접 수행 5. 합계 21.
- 두 세부 작업 모두 직접 수행 확인 가정: 연관성 15. 신뢰 가능한 원문 및 사용자 사실 확인을 가정.
- 기업규모 대기업 가정: 25. 정규직 10 + 지속성 조건 충족 5 = 15.
- 비교 기준액 B=5,000만원, 같은 구성의 연간 보상범위 6,000~7,000만원 가정: 하한비율 1.2이므로 30점. 실제 사용자 연봉이 아님.
- 복지: 주거·식사통근·건강·생활가족 네 분야 적용 확인, 교육휴식의 추가 제도 없음 확인 가정: 12점.
- 제조 전력 유틸리티 범위 확대 4 + 운영·예방점검 중심 2 = 경력가치 6.

### 8.2 결과 및 해석

| 평가 | 항목 점수 | 결과 |
| --- | --- | --- |
| Gate | 3개 필수 요건군 충족 | 지원가능 |
| 채용 적합도 | 26 + 21 + 20 + 15 + 10 | 92 |
| 회사 매력도 | 30 + 25 + 15 + 12 + 6 | 88 |
| 최종점수 | 92×0.6 + 88×0.4 | 90.4, S |

현재 경력 활용도가 높아 S가 나올 수 있지만, 생산설비 PLC·구동계 정비 확장에 만점을 부여하지 않는다. 같은 사실·경험 활용 점수를 가진 생산설비 전기보전 공고가 직무일치 30, 경력가치 10이면 적합도 96·매력도 92·최종 94.4로 더 높다. 실제로 기술·경험 대응이 떨어지면 이 비교의 전제가 성립하지 않는다.

## 10. Schema 외 필수 의미 검증

다음은 구현 단계의 저장 전 필수 검증 계약이다. JSON Schema만으로 항목 합계·필드 간 관계·근거의 진위를 검증할 수 있다고 가정하지 않는다.

1. 항목 키와 id가 일치해야 한다. `experience.components`는 inspection/diagnosis/repair/safety/records 각 5점, `employment.components`는 contract 10·continuity 5점, `benefits.components`는 다섯 분야 각 3점, `career_value.components`는 expansion 6·ownership 4점으로 정확히 한 번씩 존재해야 한다. 그 외 항목의 components는 빈 목록이다.
2. 모든 항목·하위항목은 0≤lower≤upper≤max_score다. known은 score=lower=upper이고, unknown은 score=null이다. known 단계값은 4~5절의 허용 점수 또는 명시적 비율 산식과 일치해야 한다. 사용하지 않는 임의 중간 점수는 거부한다.
3. 하위항목 합계, 두 축 합계·범위, 0.6/0.4 최종값, 정보 충족률, 등급을 입력 스냅샷에서 다시 계산한다. 여섯째 자리 저장 반올림 오차 이외의 차이를 허용하지 않는다. 등급은 원계산값 기준이므로 표시값에서 역산하지 않는다.
4. 모든 evidence_ids는 동일 출력의 evidence.id를 참조한다. ID 중복은 금지한다. 원문·경력·비교 기준의 실제 버전 및 인용 범위가 입력 스냅샷과 맞아야 한다. known 점수·확인 사실에는 높음/보통 근거가 필요하며, 점수 계산에 사용한 가장 낮은 신뢰도를 반영한다.
5. input.snapshot_ref는 영구적으로 보존된 정규화·사용자 경력·계산 입력 스냅샷을 가리킨다. 필수요건 원문·AND/OR·독립 요건군, 우대군, 기술군별 계수와 분모, 보상 B/L/U/포함항목/기간/출처를 보존한다. 이 스냅샷 없이 설명 문자열만으로 재계산하지 않는다.
6. Gate의 모든 node.id는 유일해야 한다. 노드의 result와 최상위 Gate는 원문·사용자 사실·3절의 논리로 재계산한다. 주어진 미충족이 있는데 지원가능을 반환하면 거부한다. requirements_complete=false이면 확인된 미충족이 없는 한 조건부지원이다. 단순 미기재를 해당없음으로 바꾼 입력도 거부한다.
7. 사용자 경력이 확인되지 않았다면 그 사실을 근거로 경험 미보유를 선언하거나 점수를 확정하지 않는다. 경력 기준 버전·기준일이 null이면 경력을 필요로 하는 항목을 known으로 발행하지 않는다.
8. 회사 자료는 실제 고용 법인·직무·기간에 적용되어야 한다. 보상점수가 known이면 comparison_basis_ref가 존재하고 같은 구성의 B/L/U와 근거가 스냅샷에 있어야 한다. 구간·통화·기준연도·포함 성과급 및 수당을 검사한다.
9. analysis_kind=조사반영이면 승인 이벤트를 참조해야 하며 실제 현재 승인·버전 유효성은 별도 상태 검증으로 확인한다. 이 Schema가 승인 상태를 변경하지 않는다.
10. 낮은 신뢰도와 핵심 자료 상충이 있는 항목은 unknown이어야 한다. unknowns에는 미산출 이유·추가로 필요한 정보를 기록한다. 미산출 축이 있으면 evaluation_status=정보부족, final.score와 grade는 null이다.
11. Job Family와 우선군은 MASTER 매핑을 따른다. 우선군을 배점으로 다시 더하지 않는다. 설명된 주업무와 job_match 점수는 일치해야 한다.
12. technology_matches의 task_id는 유일하고 입력 스냅샷의 확정 요구 작업 목록과 일치해야 한다. 양측 근거ID는 evidence를 참조해야 한다. null 아닌 계수에는 확인된 사용자 작업 또는 미보유 확인 근거가 필요하다. 기술군 이름만 같은 이유로 계수 1을 부여하면 거부한다. 항목 점수·범위는 세부 작업 계수에서 재계산한다. 요구 작업 목록 미확정이면 기술점수는 null·0~15이며 matches는 빈 목록이다.
13. 우대 중복 제거는 원문 논리와 필수 요건군의 포함관계를 확인한다. 선택 가능한 필수 자격 중 상위 자격을 따로 우대하는 경우를 제거하면 거부한다.
14. 테스트 자료는 is_synthetic=true이며 evidence.kind=합성테스트를 사용한다. 실제 평가에 합성 근거를 혼합하거나 테스트 ID로 실제 원문·승인을 참조한 것처럼 저장하지 않는다.

## 11. DATA_MODEL 매핑

새 Notion 속성을 필수로 추가하지 않는다. 세부 범위·충족률·구조화 JSON은 기존 ‘분석 상세’ 본문의 계약으로 저장한다.

| 출력 | 저장 위치 |
| --- | --- |
| analysis_id, job_id, analysis_kind, input 버전·참조 | Analyses의 분석 ID·공고 Relation·분석 종류 및 관련 버전 필드 |
| gate.result / mandatory_status | 지원 가능 Gate / 필수조건 충족 여부 |

| final.score / final.grade | 최종 지원 우선순위 / 최종 등급. null을 0 또는 D로 변환 금지 |
| evaluation_status | 평가 상태 |
| 항목·하위항목·범위·충족률·Gate 트리·technology_matches·근거·미확인 목록 | 분석 상세 본문 |
| 입력 스냅샷 | 분석 상세의 입력 스냅샷 섹션; snapshot_ref가 동일 스냅샷을 참조 |
| strengths / improvements / experience_gaps | 본문 상세와 Jobs·Analyses의 해당 요약 필드 |

검증된 분석만 유효로 발행하고 Jobs의 최신 유효 분석 및 요약값을 동기화한다. 형식·의미 검증 실패는 재평가 대상으로 기록하며, 정상적인 정보부족 결과와 오류를 구분한다.

## 12. 검증 결과 및 한계

v1.0의 아래 12개 묶음은 당시 검증 기록이다. v1.1의 추가 검증 결과는 변경 이력 아래에 별도로 기록한다. 기존 검증을 모든 개정 규칙의 실행 검증으로 확대 해석하지 않는다.

- 문서 내 JSON Schema의 Draft 2020-12 적합성을 검사했다.
- 합성 정상 결과, 보상·기업규모 누락, 필수요건 미충족 산술, AND/OR, 등급 경계, 잘못된 값·필드·승인·근거 참조를 포함하여 **12개 검증 묶음이 통과**했다. 등급 경계 묶음에는 6개 숫자를 포함했다.
- 정상 예시 92/88/90.4, 보상 누락 최종 범위 78.4~92.4, 기업규모 누락 80.4~90.4, 필수 1군 미충족 최종 86.4를 검산했다.
- 8.3절의 문항·의미 판단 시나리오는 설계 검토도 포함한다. 모든 실제 원문 해석이나 실제 n8n·Notion 실행을 시험했다는 뜻이 아니다. 10절 전체의 운영용 검증기 구현은 STEP 4 이후 범위다.
- 합성 예시의 순위는 설계 논리의 일관성을 확인한다. 실제 채용 결과로 평가 정확도를 검증한 것은 아니며, 실제 공고를 수집한 뒤 사용자 판단과 비교할 필요가 있다.

실제 점수 운영 전 필요한 입력:

- 사용자 비교 기준 연봉과 포함 범위·기준연도. 제공 전 보상점수와 완전한 최종점수는 미산출로 유지한다. STEP 3을 시작하는 데 필수는 아니다.
- 경력 사실·업무 수행 범위·기간·자격·학력의 확인 스냅샷. 기존 프로필을 출발점으로 삼되 미확인 기술경력이나 성과를 추가하지 않는다.
- 승인 후 실제 회사 자료의 확보 가능성. 근거가 계속 없으면 조사반영 단계에서도 정보부족이 정상 결과다.

## 14. 참고 및 변경 이력
