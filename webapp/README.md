# 승인 공고·자기소개서 UI

기존 STEP4 옆에서 독립적으로 실행하는 로컬 웹앱입니다. Python 3.12 표준 라이브러리만 사용하므로 npm/pip 설치가 필요하지 않습니다. HTML을 더블클릭하는 대신 아래 서버를 실행하세요.

## Windows에서 먼저 화면 확인

ZIP을 압축 해제하고, `MASTER_SPEC.md`와 `webapp` 폴더가 있는 위치에서 PowerShell을 엽니다.

```powershell
py -3.12 webapp\app.py --demo
```

브라우저 주소창에 `http://127.0.0.1:8000`을 입력하세요. 종료는 터미널에서 Ctrl+C입니다. `py` 명령이 없다면 Python 3.12를 설치하거나 동일 버전의 `python` 명령을 사용하세요.

데모는 `webapp/state/demo.sqlite`에 합성 공고 4개와 공고별 문항 2개를 저장합니다. 상태 변경과 답변은 서버를 다시 실행해도 유지됩니다. Notion, STEP4 SQLite, n8n에는 접근하지 않습니다. 데모에서는 AI 외부 호출도 하지 않습니다.

초기 데이터를 다시 보고 싶다면 다른 데모 DB로 실행할 수 있습니다. 기존 파일을 삭제할 필요가 없습니다.

```powershell
py -3.12 webapp\app.py --demo --demo-db webapp\state\demo-new.sqlite
```

## 실제 Notion 연결

기존 n8n(5678)과 pipeline(8787)은 그대로 둡니다. 웹앱은 8000 포트를 사용하며 두 기존 서비스가 없어도 Notion에 직접 연결할 수 있습니다. 기존 워크플로를 다시 가져오거나 `build_workflows.py`를 실행하지 마세요.

```powershell
Copy-Item webapp\.env.example webapp\.env
notepad webapp\.env
```

위 복사는 `.env`가 아직 없을 때 한 번만 실행하세요. 파일이 이미 있다면 기존 값을 유지하며 편집하세요. Notion Integration token을 `NOTION_TOKEN`에 로컬로 입력합니다. 채팅이나 프론트엔드에 입력하지 않습니다. 같은 Integration에 두 데이터 소스의 읽기·수정 권한이 필요합니다. ID는 제공된 값이 템플릿에 들어 있습니다.

```powershell
py -3.12 webapp\app.py
```

시작 시 두 DB의 필요한 속성 타입과 선택값을 읽기 전용으로 확인합니다. 불일치하면 서버를 시작하지 않고 속성명을 안내합니다. DB 속성을 자동 생성하거나 이름을 바꾸지 않습니다. 실행 후 브라우저 주소는 데모와 동일합니다. 환경변수를 수정하면 서버를 재시작하세요.

포트가 사용 중이라면 `--port 8001`로 실행하고 브라우저 주소의 포트도 바꾸세요. 서버는 항상 `127.0.0.1`에 바인딩합니다. Docker Compose 설정 변경은 필요하지 않습니다.

## 사용 방법

1. 공고 검토에서 상세 보기로 이동합니다. 원문·조건·누락정보를 확인합니다.
2. 승인/보류/제외/검토대기를 선택하면 Notion의 `사용자상태`를 변경합니다. Jobs 승격·분석 Workflow는 실행하지 않습니다.
3. 승인 공고 목록 또는 승인된 상세 화면의 `자소서 작성`으로 이동합니다.
4. 문항별 `작성방식`, `답변초안`, `작성상태`를 선택·입력하고 `답변 저장`을 누릅니다.
5. 새로고침해 저장 결과를 확인합니다. `완료`는 글 작성을 마쳤다는 표시이며 자동 지원·제출은 하지 않습니다.

문항은 기존 Notion DB에 등록된 것을 조회합니다. UI에서 문항 자체를 생성·수정·삭제하는 기능은 이번 범위에 포함하지 않았습니다. 문항이 없으면 해당 DB에 등록하고 `후보ID`를 공고의 `후보ID`와 정확히 같게 입력한 뒤 `문항 다시 불러오기`를 누르세요. 문항명은 회사마다 같아도 되며, 연결은 텍스트형 후보ID로 판단합니다. 이 값은 Notion 페이지 ID나 Data Source ID와 다릅니다.

## 사용하는 자소서 속성

| 속성 | 타입 | 값/역할 |
|---|---|---|
| 문항명 | 제목 | 화면 제목 |
| 글자수제한 | 숫자 | 최대 글자 수. 미등록이면 미확인으로 표시 |
| 답변초안 | 텍스트 | 사용자가 저장한 답변 |
| 문항내용 | 텍스트 | 실제 문항 |
| 문항번호 | 숫자 | 표시 순서 |
| 작성방식 | 선택 | `AI초안` / `직접 작성` |
| 작성상태 | 선택 | `입력대기` / `작성중` / `완료` |
| 후보ID | 텍스트 | Candidates의 후보ID와 동일 |

공백 포함 여부를 저장하는 속성이 없으므로, 이번 UI는 공백 포함 글자 수를 사용합니다. Python/브라우저 모두 Unicode code point 기준으로 계산합니다. 실제 채용 사이트의 바이트 제한과는 다를 수 있습니다. 제한 초과 답변과 빈 답변의 완료 처리는 저장하지 않습니다.

## AI 초안 설정 — 선택 사항

작성방식 `AI초안` 선택 자체는 저장할 수 있습니다. 실제 생성 버튼은 AI 키, 모델, 확인된 경력 파일이 모두 설정된 경우에만 활성화됩니다. 설정이 없으면 직접 작성·저장은 계속 사용할 수 있습니다.

이 구현의 제공자는 OpenAI Responses API입니다. `webapp/.env`에 다음을 설정하세요.

```dotenv
AI_API_KEY=본인의_키를_로컬에서_입력
AI_MODEL=계정에서_사용할_모델_ID
CAREER_FACTS_FILE=C:/절대경로/verified-career.json
```

경력 파일 형식은 아래와 같습니다. 예시는 사용자 경력을 주장하는 데이터가 아니므로 실제로 확인한 경험으로 작성하세요. `verified: true`인 사실만 전송합니다.

```json
{
  "facts": [
    {"id": "experience-001", "text": "사용자가 확인한 실제 수행 업무와 담당 범위", "verified": true}
  ]
}
```

생성 버튼은 문항·회사·제목·확인된 경력 근거를 OpenAI API에 전송하며 사용료가 발생할 수 있습니다. 요청은 서버에서 실행하고 `store: false`로 보냅니다. 기존 답변이 있으면 자동 덮어쓰기를 거부합니다. 생성 결과는 `AI초안 / 작성중`으로 저장하며 자동 완료하지 않습니다. 부족한 근거, 잘못된 근거 ID, 글자 수 초과, 생성 중 승인 철회 또는 입력 변경은 저장을 차단합니다. 근거 ID 검사는 문장 전체의 사실성을 보장하지 않으므로 사용자가 내용을 검토해야 합니다.

## 승인 검사와 동시 수정

문항 조회·답변 저장·AI 생성마다 Notion의 현재 승인 상태를 읽습니다. 다른 후보의 문항 ID로 저장하는 요청도 거부합니다. 화면 버튼을 숨기는 것 외에 API에서도 검사합니다.

답변과 공고 상태 저장에는 버전 확인을 사용합니다. 변경된 자료를 오래된 화면으로 덮어쓰면 409를 반환합니다. 저장 충돌 시 입력 답변을 복사해 보관하고 다시 조회하세요. 서버 내 작업은 직렬화하며 AI 호출 동안은 잠금을 해제해 승인 철회가 가능하도록 했습니다.

Notion에는 조건부 원자적 PATCH가 없으므로 최종 확인과 저장 사이에 Notion 직접 편집이나 다른 서버에서 일어나는 변경까지 원자적으로 차단하지는 못합니다. 같은 DB를 사용하는 웹앱 서버는 하나만 실행하고, 동시에 같은 항목을 Notion에서 직접 편집하지 않는 방식으로 운영하세요. 승인 이벤트 이력·승인 버전·Jobs 승격은 기존 설계의 후속 구현 범위입니다.

이 웹앱은 개인 PC용 로컬 서버입니다. 인터넷 공개 배포용 사용자 로그인 시스템은 포함하지 않았습니다. Host 검사, 동일 출처와 CSRF 검사, 응답 CSP, 고정 정적 파일 경로를 적용했으며 `.env`를 웹으로 제공하지 않습니다. TLS 검증을 비활성화하지 않습니다.

## 테스트

압축 해제한 프로젝트 루트에서 실행합니다.

```powershell
py -3.12 -m unittest discover -s webapp/tests -v
py -3.12 -m unittest discover -s step4/tests -v
```

신규 테스트는 실제 로컬 HTTP 요청, 모든 미승인 상태 차단, 후보–문항 연결, 답변 저장과 재시작, 버전 충돌, 정확한 선택값, 글자 수 제한, AI 미설정, 승인 철회·문항 변경 중 AI 응답 저장 차단, Notion payload와 페이지네이션을 검증합니다. Notion/AI는 모의 구현이므로 실제 외부 연결 성공을 뜻하지 않습니다.

수동 확인:

- 승인되지 않은 공고의 `#questions/후보ID` 주소를 직접 열어 차단되는지 확인합니다.
- 승인 후 문항을 열어 답변 저장 → 새로고침 → 답변/작성상태 유지 여부를 확인합니다.
- 다른 탭에서 같은 답변을 저장한 뒤 원래 탭에서 저장하면 충돌이 표시되는지 확인합니다.
- 문항을 열어 둔 채 공고를 보류로 바꾸고 저장하면 차단되는지 확인합니다.
- 390px 너비와 데스크톱에서 입력 폼이 표시되는지 확인합니다.
