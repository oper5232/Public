## 캐시 업데이트 뒤 버튼 응답 문제 수정

사용자 신고 후 기존 PWA와 GitHub Pages의 HTTP 캐시(최대600초)가 함께 남는 조건을 추가로 검사했습니다. 이전 설치 코드에서는 ‘새 버전 적용’ 후에도 HTML과 JavaScript가 모두 이전 버전1로 남는 문제를 재현했습니다. 구 HTML에서 새 스크립트가 `homeTools` 요소를 찾지 못하면 문제 시작 버튼이 `classList` 오류로 화면을 전환하지 못하는 경우도 재현했습니다.

수정 사항:

- 새 서비스워커의 앱 파일 저장은 HTTP 캐시를 다시 검증하는 `cache: reload` 요청으로 수행합니다.
- 구 HTML에서도 계정 패널을 찾아 화면을 전환하는 호환 처리를 추가했습니다.
- 업데이트 버튼은 적용 중 상태와 실패 메시지를 표시하고, 다른 탭이 먼저 업데이트해 대기 워커가 사라진 경우에도 다시 확인 후 최신 화면으로 이동합니다.
